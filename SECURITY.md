# Security and research-data handling

Do not post medical report text, patient identifiers, credentials, or unreviewed workbooks in public issues, logs, or pull requests. Use synthetic examples when reporting a defect.

Review both current files and Git history before public distribution. Confirm data-owner authorization and inspect derived prompts, caches, and outputs as well as original reports. Documentation cleanup does not certify that this repository is de-identified or approved for publication.

Revoke or rotate credentials at the issuing service if they were committed. Deleting a file does not invalidate credentials or remove copies from history. Any data removal, visibility change, or history rewrite should be reviewed separately.
